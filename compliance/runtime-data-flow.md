# Runtime data flow — 20 September 2026

This is an engineering inventory, not approved privacy policy or certification.

- Studio rendering, QR payload composition, image processing and scan decoding remain local. Explicit browser saves persist the draft, complete artifact and five previous versions in IndexedDB. They may contain Wi-Fi passwords or contact details. Local archive is reversible; clearing site data removes copies. Explicit cloud saves and hosted-page uploads have separate server flows below.
- Only an explicitly submitted artwork prompt (8–800 characters) and selected style reach Vercel's server proxy and Cloudflare Workers AI FLUX.1 Schnell. The app does not store prompts. Never claim provider-side zero retention without contractual evidence.
- Generated JPEGs are stored briefly in project-specific D1. Owner cookies bind retrieval; a daily salted network HMAC enforces quotas without storing raw IP addresses. The cookie is HttpOnly, SameSite Strict, Secure in production and renewed for two hours before generation. Retrieval is unavailable after one hour. Hourly cleanup deletes image bytes within two hours and quota metadata after three days. An aborted browser request may still finish generation and consume its allowance.
- Atomic D1 reservations enforce three generation attempts per network per UTC day, 50 globally. A shared office network shares its allowance. A server-only service secret protects all Worker endpoints. Public image creation is available only through the origin-checked, bounded proxy. No prompt, QR content or secret is logged by application code. Hosting infrastructure may retain separate access logs; review platform retention and access.
- Google sign-in uses an owner-approved web OAuth client, initially in external testing mode with the owner added as a test user. Server credentials are stored in Vercel and the private local test configuration; deployment and genuine sign-in evidence are tracked separately. PKCE/state/nonce, verified Google identity, HttpOnly signed session, canonical callback and same-origin writes protect access. No OAuth tokens go to browser storage. Signed sessions last seven days; centralized revocation/offboarding is not yet implemented.
- Hosted-page and dynamic-link drafts survive ordinary in-app navigation in memory. Choosing “Keep draft in this tab and sign in” explicitly stores up to 32 KiB of structured draft text and file identifiers in this tab's sessionStorage, with a 30-minute expiry. Uploaded file bytes and credentials are excluded. The transfer is removed on return and rejected when a previously signed-in owner does not match; logout invalidates pending editor responses.
- Optional cloud saves use D1 metadata scoped to the authenticated Google subject hash, and private R2 JSON objects. Save is explicit, limited to 3 MB/design and 50 designs/account including archives. Objects contain destination, uploaded image, portrait and rendered PNG; SVG and client-supplied scan assertions are omitted. Reopening rerenders and revalidates. No public R2 URL or hosted landing page is created. A cloud copy has no version history, automatic sync, permanent deletion or tenant/team controls yet.
- Updates publish a new private object and compare the previous pointer before replacing metadata; failed writes retain the old version. Rare terminated reservations may consume quota until operator reconciliation. Operational backup/restore, orphan reconciliation and rights-request procedures must be completed before enterprise account rollout.

- Dynamic links use authenticated owner-scoped D1 rows, with up to 50 including archived entries. Creation is a private draft; publish explicitly enables the immutable short URL. Changing a published target changes its redirect immediately. Pause/archive disables resolution. Counts are daily aggregate opens, including bots/repeats, with no visitor IP, user-agent, cookie, referrer or unique-person profile stored in the counter. Destination URLs are validated HTTPS but never fetched by the service. DNS ownership and target content are not certified safe by URL validation.
- Hosted pages store structured drafts separately from the published snapshot. Link pages, menus, galleries, PDF downloads and feedback forms publish only after an explicit action; private edits do not replace the snapshot. Limits: 50 pages and 100 uploaded files per account, including archives; 12 items per page, 2 MiB per file. Uploads go to private R2. Public file delivery verifies current publication, snapshot membership and ownership each time. Images use fixed raster MIME and bounded dimensions; PDFs are untrusted attachment downloads, not inline documents. Header validation is not antivirus or full file decoding.
- Feedback submissions are stored privately for the page owner: optional name/email, message and creation time. Consent is required. Raw IP, user-agent and referrer are not stored. A server-secret HMAC of the trusted Vercel ingress IP and UTC date enforces five submissions/network/hour. Each form also allows 100/day and 1,000 retained messages. Old network-quota hashes are pruned opportunistically after two days; message deletion/retention procedures are pending owner approval. No notification emails are sent. An owner must not request sensitive personal data through the generic form.
- Billing code is gated by provider secrets, validated price IDs and an explicit activation flag. No merchant account, approved offers or live charges are configured by this implementation. Stripe-hosted checkout and portal keep payment-card entry outside the app. Any future billing activation adds Stripe as a supplier and requires actual contractual/privacy/payment-scope review.

Active runtime suppliers: Vercel (web/proxy), Cloudflare (DNS, Workers AI, D1 and private R2). Google is configured for authentication testing; Stripe CLI sandbox access is authorized, while application billing remains disabled. No third-party visitor analytics provider is active. Suppliers, processing locations, data agreements and policy notices need accountable owner approval; these technical controls do not establish SOC 2, ISO 27001 or legal compliance.
